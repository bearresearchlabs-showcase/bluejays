BLUEJAYS is not a dataset — it is a suite of executable environments. Sixteen production-domain PostgreSQL databases with 480 gold question–SQL episodes, BIRD-superset annotation, hardened per-environment containers, engineered partial observability, and a property no public benchmark can keep: contamination-free provenance by construction — the corpus was sourced under rules requiring that its content never be webcrawlable, so it cannot have been in any model's pretraining data.

The blue jay is a corvid — the bird family that collects, caches, and remembers the provenance of everything it stores. This suite holds itself to the same standard: the full forensic construction record, including known defects, ships with the benchmark.

Why BLUEJAYS

Environments, not files. Every database ships as executable DDL + data with a hardened container, so the reward function — execution accuracy against materialized gold output — is runnable, not merely described. An episode is a POMDP step: observation (question + evidence + partial schema), action (SQL), reward (result match).
Partial observability by design. Agents see a per-query schema subset, never the full DDL — simulating real-world schema retrieval instead of the full-schema fiction of classic benchmarks.
Radical provenance honesty. The construction record is part of the release: what was exported from live systems, what was purpose-built from public/government sources, which rows are synthetic, which defects are open. A benchmark that hides its flaws contaminates every conclusion drawn on it.

Example Episode (db-6 · Weather/Insurance · PostGIS · Query 26, challenging)

Observation — question: "Can you show me the storm cell tracking and movement analysis from NEXRAD radar data?"

Policy context — evidence (excerpt): "A weather consulting firm providing insurance risk assessment needs to analyze severe weather events. NEXRAD radar systems track storm cells in real-time … the query joins NEXRAD radar observations with spatial boundaries, groups storm cells by unique identifiers and time intervals, calculates aggregate metrics including maximum reflectivity and cell velocity vectors, applies window functions to compute movement trends…"

Gold action — sql (head of 10,235 chars):

WITH time_window AS (
    -- Define time window for tracking (last 2 hours)
    SELECT CURRENT_TIMESTAMP - INTERVAL '2 hours' AS window_start,
           CURRENT_TIMESTAMP AS window_end
), ...
