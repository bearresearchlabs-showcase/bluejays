Act I — The Ask

"Acquire real-world databases and accompanying query notebooks to support downstream evaluation and training. All assets must reflect authentic, real-world usage (no synthetic datasets, no synthetic queries)."

"10 databases = 8-12 hours of work (per expert consultant)"

But the attached hard requirements quietly describe something else: zero synthetic data (with forensic validation), sources that must not be webcrawlable (contamination-free by construction), 30 extremely complex queries per database, queries that chain into workflows, and queries modelable as a graph reducible by shortest-path algorithms. That is not a sourcing spec. That is the raw material of a training environment.

Act II — What Shipped

The ask, at face value

  • ~10 databases
  • Query notebooks
  • 8–12 hours of sourcing

The delivered system

  • 16 production-domain PostgreSQL databases, ~14 GB real extracted data
  • 480 gold pairs with BIRD-superset annotation (question, evidence, schema_context, expected_output)
  • 16 hardened Postgres containers — one live environment instance per database
  • BIRD / BIRD-CRITIC / workbench export pipeline (23 files)
  • Validation notebooks, integrity hashes, K8s jobs, 5 apps, deployed docs site
  • A metadata schema with a field named rl_ready

The objection This scope was called overengineering — "a cost center." The answer It is the minimum viable structure of an RL-environment-grade corpus — the exact product category positioned as the frontier-lab differentiator ("RL Environments — Unique"). Acts III–IV show the structure was there all along.

Act III — The Tuple Nobody Named

Three project documents independently wrote the RL framing without ever saying "MDP" or "Markov" (neither word appears anywhere in the repo before this narrative):

  • client/README.md — "Use question as the user utterance (state/observation), sql as the gold action… Use execution success, result correctness… as reward signals."
  • template/queries.md — a five-stage training pipeline: input prompt → golden output → reward signal → curriculum control → evaluation (EX/EM).
  • client/doc/README.md — "Agentic loop: Plan → Act (run SQL) → Observe → Reflect (verify) → Iterate."

The honest position: no Spider 2.0 integration exists in this repository — the term appears nowhere before this narrative. What exists is the unique property public benchmarks cannot keep: the corpus can never have been in a model's pretraining data, because not being webcrawlable was a sourcing rule, not an afterthought. The seeds of Spider2-grade structure are already in the original spec: query chaining (multi-step episodes) and the query graph (Dijkstra-reducible transition structure).

Act VI — Provenance & the Frontier Moment

What actually shipped (forensic record)

  • 13 databases, 390 pairs, 19.4 GB delivered March 2026 (db-2, db-3, db-6…db-16)
  • The provenance pivot: real production exports (db-1/4/5) were cut; from db-6 on, databases were purpose-built mirrors of named commercial systems fed by public/government sources
  • Rows synthetic, schemas real — "No row of shipped data is real production data; no schema is arbitrary"
  • Industrialization day, Feb 18, 2026: 9 schemas at 06:54; thirteen 1 GiB datasets written in a two-minute window
  • Client verdict: "Databases look good, only comment: the descriptions are AI-generated" → measured (mean 193 chars, 0/390 name intent) → active remediation with acceptance criteria
  • Full record: docs/provenance/ — every figure recomputed from shipped files, 2026-08-05

How frontier was this, actually

  • Feb 5, 2026 — OpenAI announces Frontier: enterprise agents onboarded and managed like employees, with feedback loops. Frontier labs (incl. Meta Superintelligence Labs' agent-focused Muse line) define the category through 2026
  • Feb 14–18, 2026 — the same month, this engagement's SOW positions against BIRD-SQL/LiveSQLBench and the environment factory industrializes
  • The claim, soberly: an ask scoped as data sourcing produced the exact substrate the frontier-agent category consumes — private RL environments with gold actions, executable reward, and curriculum structure. Contemporaneous with the platform wave, not derivative of it
  • The named gap is the frontier gap: the record itself states that annotation alone cannot prove data trains agents — execution-accuracy harnesses and BIRD/Spider ablations can. That is roadmap P0 — partially closed 2026-08-05: 288/480 gold queries executed live on fresh instances, with the failure taxonomy and defect ledger in docs/TECHNICAL_EXECUTION.md

Roadmap — Verified Today vs. Spider2-Grade

Verified today

  • Single-turn episodes, executable gold actions
  • 16 live PostgreSQL environments
  • BIRD-superset annotation + exports
  • Partial-observability by design (schema_context)
  • Contamination-free provenance

Spider2-grade (forward-looking)

  • P0 — Close the evaluation loop: run CRITIC/workbench live (fix the 0/3)
  • P1 — Chain queries into multi-step episodes via the query graph
  • P2 — Cross-database workflow tasks (weather ↔ flood ↔ maritime)
  • P3 — Dialect expansion (Snowflake/BigQuery) + ambiguity injection
