## Database Overview

The Electricity Cost and Solar Rebate Database (db-15) provides comprehensive data on electricity rates across the United States, organized by rate codes, utilities, and geographic regions. The database also includes extensive solar panel rebate and incentive information from federal, state, and utility sources.

This database is designed to mirror and index the electricity rate and solar rebate data available from poweroutage.us and other reputable sources, providing marketing insights and comprehensive cost analysis for electricity consumers and solar energy adopters.

- **Comprehensive Rate Data**: Electricity rates from 3,700+ U.S. utilities organized by rate codes
- **Geographic Analysis**: Location-based rate queries by state, county, and zip code
- **Rate Structure Analysis**: Support for tiered rates, time-of-use rates, and demand charges
- **Solar Rebate Database**: Federal, state, and utility-level solar rebates and incentives
- **Historical Trends**: Historical rate data for trend analysis and forecasting
- **Cross-Source Validation**: Data validated against multiple authoritative sources

- **PostgreSQL**: Full support with standard SQL features
- **, **: Compatible with Delta Lake and distributed query execution
- **, **: Full support with standard SQL features

- **OpenEI Utility Rates API**: Comprehensive utility rate database (3,700+ utilities)
- **EIA Form 861**: Annual Electric Power Industry Report
- **EIA State Electricity Profiles**: State-level electricity prices
- **DSIRE**: Database of State Incentives for Renewables & Efficiency
- **DOE Tax Credits**: Federal solar and renewable energy incentives
- **EPA Energy Star**: Energy Star rebate finder
- **State Utility Commissions**: State-specific rate filings
- **PowerOutage.us**: Electricity rates organized by rate codes
- **Data.gov**: Additional federal electricity datasets

## Query 1: Multi-Level Electricity Rate Analysis with Geographic Aggregations and Rate Code Analysis {#query-1}

**Use Case:** **Utility Rate Analysis Platform - Comprehensive Rate Analysis Dashboard for Energy Consultants**

**Description:** Description: Enterprise-level electricity rate analysis with multi-level CTE nesting, geographic aggregations, rate code classifications, utility comparisons, and advanced window functions. Demonstrates production patterns used by energy consulting firms and utility rate intelligence platforms. Use Case: Utility Rate Analysis Platform - Comprehensive Rate Analysis Dashboard for Energy Consultants Business Value: Comprehensive rate analysis report showing rates by state, utility, rate code, and g

**Business Value:** Comprehensive rate analysis report showing rates by state, utility, rate code, and g

**Complexity:** Deep nested CTEs (7+ levels), geographic aggregations, complex joins across multiple tables, window functions with multiple frame clauses, percentile calculations, rate trend analysis, correlated subqueries

```sql
WITH state_rate_summary AS (
    -- First CTE: Aggregate rates by state with comprehensive metrics
    SELECT
        s.state_id,
        s.state_name,
        s.region,
        s.division,
        COUNT(DISTINCT er.utility_id) AS utility_count,
        COUNT(DISTINCT er.rate_code_id) AS rate_code_count,
        COUNT(DISTINCT er.rate_id) AS total_rate_count,
        AVG(er.energy_charge_usd_per_kwh) AS avg_energy_charge,
        PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY er.energy_charge_usd_per_kwh) AS median_energy_charge,
        PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY er.energy_charge_usd_per_kwh) AS q1_energy_charge,
        PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY er.energy_charge_usd_per_kwh) AS q3_energy_charge,
        MIN(er.energy_charge_usd_per_kwh) AS min_energy_charge,
        MAX(er.energy_charge_usd_per_kwh) AS max_energy_charge,
```

## Query 2: Recursive Rate Structure Analysis with Tiered Rate Calculations and Time-of-Use Optimization {#query-2}

**Use Case:** **Energy Cost Optimization Platform - Tiered Rate and TOU Analysis for Commercial Energy Management**

**Description:** Description: Enterprise-level recursive rate structure analysis using recursive CTE for tiered rate calculations, time-of-use period analysis, rate optimization scenarios, and multi-level rate structure traversal. Implements production patterns for analyzing complex rate structures with multiple tiers and TOU periods. Use Case: Energy Cost Optimization Platform - Tiered Rate and TOU Analysis for Commercial Energy Management Business Value: Comprehensive tiered rate and TOU analysis showing optim

**Business Value:** Comprehensive tiered rate and TOU analysis showing optim

**Complexity:** Advanced recursive CTE with tier calculations, TOU period analysis, multi-level rate structure traversal, usage scenario modeling, cost optimization calculations, multiple CTE nesting levels (6+)

```sql
WITH RECURSIVE tiered_rate_calculations AS (
    -- Anchor CTE: Base tier calculations for tiered rates
    SELECT
        trt.tier_id,
        trt.rate_structure_id,
        trt.tier_number,
        trt.tier_name,
        trt.tier_start_kwh,
        trt.tier_end_kwh,
        trt.energy_charge_usd_per_kwh,
        rs.utility_id,
        rs.rate_code_id,
        er.state_id,
        -- Calculate tier range
        CASE
            WHEN trt.tier_end_kwh IS NULL THEN 999999
            ELSE trt.tier_end_kwh - trt.tier_start_kwh
        END AS tier_kwh_range,
        -- Tier usage scenarios
        0 AS cumulative_kwh_usage,
        trt.tier_start_kwh AS scenario_start_kwh,
        COALESCE(trt.tier_end_kwh, 999999) AS scenario_end_kwh
    FROM tiered_rate_tiers trt
    INNER JOIN rate_structures rs ON trt.rate_structure_id = rs.rate_structure_id
    INNER JOIN electricity_rates er ON rs.rate_structure_id = er.rate_structure_id
    WHERE rs.is_current = TRUE
        AND er.is_current = TRUE
        AND trt.expiration_date IS NULL OR trt.expiration_date > CURRENT_DATE

    UNION ALL

    -- Recursive step: Calculate cumulative tier costs
    SELECT
        trc.tier_id,
        trc.rate_structure_id,
        trc.tier_number,
        trc.tier_name,
        trc.tier_start_kwh,
        trc.tier_end_kwh,
        trc.energy_charge_usd_per_kwh,
        trc.utility_id,
        trc.rate_code_id,
        trc.state_id,
        trc.tier_kwh_range,
        trc.cumulative_kwh_usage + trc.tier_kwh_range,
        trc.scenario_start_kwh,
        trc.scenario_end_kwh
    FROM tiered_rate_calculations trc
    INNER JOIN tiered_rate_tiers trt ON (
        trt.rate_structure_id = trc.rate_structure_id
        AND trt.tier_number = trc.tier_number + 1
    )
    WHERE trc.cumulative_kwh_usage < 10000
),

    SELECT
        tou.tou_period_id,
        tou.rate_structure_id,
        tou.period_name,
        tou.period_start_time,
        tou.period_end_time,
        tou.day_of_week,
        tou.season,
        tou.energy_charge_usd_per_kwh,
        rs.utility_id,
        rs.rate_code_id,
        er.state_id,
        -- Calculate period duration in hours
        CASE
            WHEN tou.period_end_time > tou.period_start_time THEN

            ELSE
                EXTRACT(EPOCH FROM (tou.period_end_time + INTERVAL '24 hours' - tou.period_start_time)) / 3600

        -- Period cost scenarios

            WHEN tou.period_name LIKE '%Peak%' THEN 'High Cost'

        AND er.is_current = TRUE

        usage_kwh,
        usage_scenario_name

            (1000, 'Medium Usage'),

        trc.state_id,
        usm.usage_kwh,
        usm.usage_scenario_name,
        SUM(
            CASE
                WHEN usm.usage_kwh >= trc.tier_start_kwh THEN
                    CASE
                        WHEN trc.tier_end_kwh IS NULL OR usm.usage_kwh <= trc.tier_end_kwh THEN
                            (usm.usage_kwh - trc.tier_start_kwh + 1) * trc.energy_charge_usd_per_kwh

                            trc.tier_kwh_range * trc.energy_charge_usd_per_kwh

                ELSE 0

        toua.state_id,

                WHEN toua.period_cost_category = 'High Cost' THEN
                    usm.usage_kwh * 0.4 * toua.energy_charge_usd_per_kwh
                WHEN toua.period_cost_category = 'Low Cost' THEN
                    usm.usage_kwh * 0.6 * toua.energy_charge_usd_per_kwh

                    usm.usage_kwh * 0.1 * toua.energy_charge_usd_per_kwh
            END
        ) AS tou_energy_cost,
        COUNT(DISTINCT toua.tou_period_id) AS tou_period_count,
        AVG(
            CASE
                WHEN toua.period_cost_category = 'High Cost' THEN toua.energy_charge_usd_per_kwh

                ELSE NULL
            END
        ) AS avg_offpeak_rate
    FROM tou_period_analysis toua
    CROSS JOIN usage_scenario_modeling usm
    GROUP BY toua.rate_structure_id, toua.utility_id, toua.rate_code_id, toua.state_id, usm.usage_kwh, usm.usage_scenario_name
),
rate_optimization_comparison AS (
    -- Sixth CTE: Compare tiered vs TOU rates for optimization
    SELECT
        COALESCE(trcc.rate_structure_id, torcc.rate_structure_id) AS rate_structure_id,
        COALESCE(trcc.utility_id, torcc.utility_id) AS utility_id,
        COALESCE(trcc.rate_code_id, torcc.rate_code_id) AS rate_code_id,

        torcc.tou_period_count,
        torcc.avg_peak_rate,
        torcc.avg_offpeak_rate,

            WHEN trcc.tiered_energy_cost IS NOT NULL AND torcc.tou_energy_cost IS NOT NULL THEN

            ELSE NULL

                    WHEN trcc.tiered_energy_cost < torcc.tou_energy_cost THEN 'Tiered Rate'

                END
            WHEN trcc.tiered_energy_cost IS NOT NULL THEN 'Tiered Rate'
            WHEN torcc.tou_energy_cost IS NOT NULL THEN 'TOU Rate'
            ELSE 'Standard Rate'
        END AS optimal_rate_type
    FROM tiered_rate_cost_calculations trcc
    FULL OUTER JOIN tou_rate_cost_calculations torcc ON (
        trcc.rate_structure_id = torcc.rate_structure_id
        AND trcc.usage_kwh = torcc.usage_kwh
    )
)

    roc.rate_structure_id,
    roc.utility_id,
    uc.utility_name,
    roc.rate_code_id,
    rc.rate_code,

    s.state_name,
    roc.usage_kwh,
    roc.usage_scenario_name,

    roc.tiers_applied,
    roc.tier_count,
    ROUND(CAST(roc.tou_energy_cost AS NUMERIC), 2) AS tou_energy_cost,
    roc.tou_period_count,
    ROUND(CAST(roc.avg_peak_rate AS NUMERIC), 6) AS avg_peak_rate,
    ROUND(CAST(roc.avg_offpeak_rate AS NUMERIC), 6) AS avg_offpeak_rate,

INNER JOIN utility_companies uc ON roc.utility_id = uc.utility_id
INNER JOIN rate_codes rc ON roc.rate_code_id = rc.rate_code_id
INNER JOIN states s ON roc.state_id = s.state_id
```

```sql
            PARTITION BY rc.state_id, rc.utility_id, rc.system_size_kw
            ORDER BY year_num

        -- 10-year NPV

            CASE WHEN year_num <= 10 THEN rc.annual_savings / POWER(1.03, year_num) ELSE 0 END

            ELSE NULL

        ROUND(CAST(npva.npv_25yr AS NUMERIC), 2) AS npv_25yr,

        ROUND(CAST(npva.total_savings_25yr AS NUMERIC), 2) AS total_savings_25yr,
        ROUND(CAST(npva.roi_25yr_percentage AS NUMERIC), 2) AS roi_25yr_percentage,
        -- Investment classification

            WHEN npva.payback_period_years <= 5 THEN 'Excellent Investment'
            WHEN npva.payback_period_years <= 8 THEN 'Good Investment'
            WHEN npva.payback_period_years <= 12 THEN 'Moderate Investment'
            ELSE 'Long-Term Investment'
        END AS investment_classification,
        -- Window functions for comparison
        AVG(npva.payback_period_years) OVER (PARTITION BY npva.state_id) AS state_avg_payback,
        AVG(npva.roi_25yr_percentage) OVER (PARTITION BY npva.state_id) AS state_avg_roi
    FROM npv_analysis npva
    WHERE npva.year_num = 1
)
SELECT

    system_size_kw, system_name, total_system_cost, total_rebates, net_system_cost,
    rebate_percentage, energy_charge_usd_per_kwh, annual_kwh_production,
    annual_savings, payback_period_years, npv_25yr, npv_10yr, total_savings_25yr,
    roi_25yr_percentage, investment_classification,
    ROUND(CAST(state_avg_payback AS NUMERIC), 2) AS state_avg_payback,
    ROUND(CAST(state_avg_roi AS NUMERIC), 2) AS state_avg_roi
```

```sql
        nma.retail_rate,
        nma.effective_export_rate,
        nma.net_metering_capacity_limit_kw,
        -- Annual savings (self-consumption + export)
        CASE
            WHEN sse.system_size_kw <= COALESCE(nma.net_metering_capacity_limit_kw, 999999) THEN
```

```sql
WITH RECURSIVE rate_code_hierarchy AS (
    SELECT
        rc.rate_code_id AS parent_code_id,
        rc.rate_code AS parent_code,
        rc.rate_code_category,
        rc2.rate_code_id AS child_code_id,
        rc2.rate_code AS child_code,
        1 AS hierarchy_level,
        ARRAY[rc.rate_code_id] AS code_path
    FROM rate_codes rc
    INNER JOIN rate_codes rc2 ON rc.rate_code_category = rc2.rate_code_category AND rc.rate_code_id != rc2.rate_code_id
    WHERE rc.is_active = TRUE AND rc2.is_active = TRUE

    UNION ALL

    SELECT
        rch.parent_code_id,
        rch.parent_code,
        rch.rate_code_category,
        rc3.rate_code_id,
        rc3.rate_code,
        rch.hierarchy_level + 1,
        rch.code_path || ARRAY[rc3.rate_code_id]
    FROM rate_code_hierarchy rch
    INNER JOIN rate_codes rc3 ON rch.rate_code_category = rc3.rate_code_category
    WHERE rch.hierarchy_level < 5
        AND NOT rc3.rate_code_id = ANY(rch.code_path)
),
hierarchy_analysis AS (
    SELECT
        rch.*,
        array_length(rch.code_path, 1) AS path_length,
        COUNT(*) OVER (PARTITION BY rch.parent_code_id) AS total_children
    FROM rate_code_hierarchy rch
)
SELECT
    parent_code_id, parent_code, child_code_id, child_code,
    rate_code_category, hierarchy_level, path_length, total_children
```
