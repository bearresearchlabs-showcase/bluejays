# Website Architecture - Complete Redesign

## Overview

The website has been completely redesigned to render all of `client/db/` with a clean, modern architecture. The site uses Vercel Blob Storage for production and falls back to local filesystem for development.

## Architecture

### Data Layer

1. **`lib/comprehensive-database.json`** - Complete structured data from all `client/db/` folders
   - Generated by: `scripts/build-comprehensive-database.js`
   - Contains: databases, schemas, queries, files, statistics
   - Source: `client/db/db-{6..15}/*/db-{N}_deliverable.json`

2. **`lib/database-index.json`** - Lightweight index for catalog/sidebar
   - Generated by: `scripts/build-website-database.js`
   - Contains: id, name, shortDescription, tableCount, queryCount
   - Used for: Sidebar navigation, quick catalog display

3. **`lib/database-content.json`** - Full HTML content for documentation pages
   - Generated by: `scripts/extract-deliverable-content.js`
   - Contains: Complete HTML from markdown files
   - Used for: Full documentation display

### API Routes

- **`GET /api/databases`** - Returns comprehensive database catalog
- **`GET /api/databases/[id]`** - Returns individual database details
- **`GET /api/databases/[id]/schema`** - Returns full schema (loads from deliverable JSON)
- **`GET /api/databases/[id]/queries`** - Returns all queries (loads from deliverable JSON)
- **`GET /api/deliverable/[id]`** - Returns deliverable JSON (tries blob storage first)
- **`GET /api/metadata/[id]`** - Returns metadata JSON (tries blob storage first)

### Pages

- **`/`** - Redirects to `/databases`
- **`/databases`** - Comprehensive catalog with search and filtering
- **`/db/[id]`** - Individual database page with tabs (overview, schema, queries, files) + full docs
- **`/db/[id]/docs`** - Full documentation view
- **`/db/[id]/metadata`** - Metadata JSON view

### Components

- **`DatabasesCatalog`** - Main catalog page with search/filter
- **`DatabaseDetailView`** - Tabbed interface for database details
- **`DatabaseContent`** - Full HTML documentation renderer
- **`Sidebar`** - Navigation sidebar with database list
- **`ClientScripts`** - Prism.js, Mermaid.js initialization

## Features

### Search & Filter
- Search by database name, description, or ID
- Filter by table count (small/medium/large)
- Real-time filtering with result count

### Statistics Dashboard
- Total databases count
- Total tables across all databases
- Total queries (300)
- Total data size (~27.6 GB)

### Database Cards
- Database ID and name
- Short description
- Table count badge (color-coded)
- Query count and data size
- Hover effects and smooth transitions

### Database Detail Pages
- **Overview Tab**: Full description with formatted text, key metrics
- **Schema Tab**: All tables with column counts
- **Queries Tab**: Query previews with complexity indicators
- **Files Tab**: Data files with sizes
- Links to full documentation below

### Blob Storage Integration
- Configured via `BLOB_READ_WRITE_TOKEN` environment variable
- API routes try blob storage first, fall back to local filesystem
- Verification script: `npm run verify-blob`

## Build Process

```bash
# Build all data structures
npm run sync-content

# Individual builds
npm run extract-content      # Build database-content.json
npm run build-website-db      # Build database-index.json
npm run build-comprehensive-db # Build comprehensive-database.json

# Development
npm run dev                   # Start dev server on :3000

# Production
npm run build                 # Build for production
npm start                     # Start production server
```

## Data Flow

1. **Source**: `client/db/db-{N}/*/db-{N}_deliverable.json` and `db-{N}.md`
2. **Extraction**: Scripts parse and structure data
3. **Storage**: JSON files in `lib/` directory
4. **API**: Routes serve structured data
5. **UI**: Components fetch and display data
6. **Blob**: Production uses Vercel Blob Storage, dev uses local filesystem
