# Hierarchical Orders (LinkWay) — Documentation

**Database:** db-3  
**Content:** Installation guide, specifications, schema, data dictionary.

---

## Purpose

This database supports analytics for hierarchical order management (LinkWay). It models parent-child order hierarchies, related line items, and cross-linked metrics. Queries use recursive CTEs and tree traversal for rollups, subtree aggregation, and depth analysis across order and supply-chain analytics.

## Schema Overview

**Total tables:** 3 (plus view `orders_order`)

- `table1` — Main hierarchy table for orders; self-referential via `parent_id` for tree traversal
- `table2` — Related line items or child records linked to `table1`
- `table3` — Cross-linked metrics joining `table1` and `table2`; used for metric and status analysis
- `orders_order` — View mapping `table1` to `seller_id`, `created_at`, `total_amount`, `status` for order analytics

**Indexes:** `idx_table1_parent_id`, `idx_table1_category`, `idx_table1_date_col`, `idx_table2_table1_id`, `idx_table3_table1_id`, `idx_table3_table2_id`

## Data Dictionary

### `table1`

Main hierarchy table. Self-referential: `parent_id` references `id`; root rows have `parent_id` NULL.

- `id` BIGINT PRIMARY KEY — Order or node identifier
- `parent_id` BIGINT — Parent order/node (FK to table1.id); NULL for root
- `name` VARCHAR(255) NOT NULL — Order or node name
- `value` NUMERIC(15,2) — Order total amount or node value
- `category` VARCHAR(100) — Category for grouping (e.g., status, type)
- `date_col` DATE — Date for temporal filtering
- `created_at` TIMESTAMP — Creation timestamp
- `updated_at` TIMESTAMP — Last update timestamp

### `table2`

Related records linked to table1. Used for line-item or child-record analytics.

- `id` BIGINT PRIMARY KEY — Record identifier
- `table1_id` BIGINT NOT NULL — Parent order (FK to table1.id)
- `related_value` NUMERIC(15,2) — Related numeric value
- `description` TEXT — Free-text description
- `date_col` DATE — Date for temporal filtering
- `created_at` TIMESTAMP — Creation timestamp

### `table3`

Cross-linked metrics joining table1 and table2. Used for metric and status analysis across hierarchy levels.

- `id` BIGINT PRIMARY KEY — Record identifier
- `table1_id` BIGINT NOT NULL — Reference to table1 (FK)
- `table2_id` BIGINT NOT NULL — Reference to table2 (FK)
- `metric_value` NUMERIC(15,2) — Metric value for aggregation
- `status` VARCHAR(50) — Status for filtering/grouping
- `created_at` TIMESTAMP — Creation timestamp

### `orders_order` (view)

View for order analytics. Maps table1 columns to `seller_id`, `created_at`, `total_amount`, `status`.
